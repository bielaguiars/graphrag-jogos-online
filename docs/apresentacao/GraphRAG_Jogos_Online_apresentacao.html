GraphRAG / KAG — Jogos Online

Tendências em Ciência da Computação · Prof. Ricardo Roberto de Lima · 18/11/2026

Biel Aguiar e Thiago Rocha · Unipê Cruzeiro do Sul

Tudo roda localmente: Neo4j 5.26 (Docker) com Graph Data Science e APOC, embeddings multilingual-e5-small na própria máquina e interface em Streamlit. Sem chave de API, o sistema funciona em modo extrativo: a resposta é montada direto das triplas do grafo.

1 - Problema e dados

O RAG vetorial devolve os trechos mais parecidos com a pergunta. Isso falha em dois casos: perguntas de vários saltos, em que cada fato está num artigo diferente, e perguntas fora da base, que ele não sabe recusar. Pergunta-guia: “Que jogo da Valve surgiu de um mod de Warcraft III?” A resposta cruza três artigos: Dota 2, Defense of the Ancients e Warcraft III.

  • 65 artigos da Wikipedia em inglês sobre jogos online (MOBAs, battle royale, FPS, MMOs, mobile e campeonatos de e-sports), divididos em 282 trechos de três frases.
  • Extração: 811 entidades e 797 relações; depois da resolução, 351 entidades canônicas, 93 delas presentes em mais de um artigo (as pontes entre documentos).
  • Avaliação com 26 perguntas em português: 12 de um salto, 9 de dois ou mais saltos e 5 fora do domínio.

2 - Arquitetura

3 - Pilar 1: Text-to-Graph (NER/RE com LLM)

  • Um LLM (Claude) extrai entidades e relações com saída estruturada: um JSON Schema gerado de modelos Pydantic, com 9 tipos de entidade (Game, Company, Person, Genre, Platform, Engine, Franchise, Event, Concept) e 13 tipos de relação (DEVELOPED_BY, BASED_ON, SEQUEL_OF, CREATED_BY, SUBSIDIARY_OF…).
  • Evidência literal: cada relação traz a frase do artigo que a sustenta, e um validador descarta a relação se essa frase não aparece no texto. É a primeira barreira contra alucinação.
  • Resolução de entidades em três passos (chave lexical, aliases compatíveis e semântica com cosseno ≥ 0,93), com travas: nomes com números diferentes nunca se fundem (Overwatch ≠ Overwatch 2).

Proveniência: a relação guarda a frase de evidência e o artigo de origem

MATCH (a:Entity {name: 'Defense of the Ancients'})-[r:BASED_ON]->(b:Entity {name: 'Warcraft III: Reign of Chaos'})
MATCH (art:Article {doc_id: r.doc_id})
RETURN a.name AS origem, type(r) AS relacao, b.name AS destino, r.evidence AS evidencia, art.title AS artigo

4 - Pilar 2: modelo LPG no Neo4j

(:Article)-[:DESCRIBES]->(:Entity), (:Chunk)-[:PART_OF]->(:Article) e (:Entity)-[:13 tipos {evidence, doc_id}]->(:Entity); cada entidade ganha também o rótulo do seu tipo (:Game, :Company…).

Constraints de unicidade e índices RANGE, FULLTEXT e VECTOR

// Constraints de unicidade
CREATE CONSTRAINT article_id IF NOT EXISTS FOR (a:Article) REQUIRE a.doc_id IS UNIQUE;
CREATE CONSTRAINT entity_id IF NOT EXISTS FOR (e:Entity) REQUIRE e.id IS UNIQUE;
CREATE CONSTRAINT chunk_id IF NOT EXISTS FOR (c:Chunk) REQUIRE c.id IS UNIQUE;
// RANGE (B-tree) para filtros e ordenação
CREATE INDEX entity_name IF NOT EXISTS FOR (e:Entity) ON (e.name);
CREATE INDEX entity_pagerank IF NOT EXISTS FOR (e:Entity) ON (e.pagerank);
// ... entity_type, article_title
// FULLTEXT (Lucene)
CREATE FULLTEXT INDEX entity_fulltext IF NOT EXISTS FOR (e:Entity) ON EACH [e.name, e.aliases_text, e.description];
CREATE FULLTEXT INDEX article_fulltext IF NOT EXISTS FOR (a:Article) ON EACH [a.title, a.text];
// VECTOR: 3 índices de 384 dimensões, cosseno (entity_vector, chunk_vector, article_vector)
CREATE VECTOR INDEX chunk_vector IF NOT EXISTS FOR (n:Chunk) ON (n.embedding)
OPTIONS {indexConfig: {`vector.dimensions`: 384, `vector.similarity_function`: 'cosine'}};

// Conferindo
SHOW INDEXES
YIELD name, type, labelsOrTypes, properties
WHERE type <> 'LOOKUP'
RETURN name, type, labelsOrTypes, properties

Esquema do grafo (db.schema.visualization)

CALL db.schema.visualization()

Tamanho do grafo carregado

MATCH (n)
RETURN labels(n)[0] AS rotulo, count(*) AS nos

5 - Pilar 3: recuperação híbrida e algoritmos de grafo

  • Ligação de entidades por três canais (vetor, fulltext e dicionário de nomes com glossário português-inglês), fundidos por Reciprocal Rank Fusion.
  • Travessia multi-hop de até 2 saltos (até 3) a partir das âncoras e allShortestPaths entre elas, preferindo caminhos por nós pouco centrais.
  • Consulta por intenção: “quem criou”, “subsidiária” viram tipos de relação. No fim, as 30 melhores triplas e os 4 trechos mais próximos formam o contexto.

Busca vetorial nos trechos (índice VECTOR)

MATCH (c:Chunk)-[:PART_OF]->(:Article {title: 'Dota 2'})
WITH c LIMIT 1
CALL db.index.vector.queryNodes('chunk_vector', 5, c.embedding) YIELD node, score
MATCH (node)-[:PART_OF]->(a:Article)
RETURN a.title AS artigo, left(node.text, 70) AS trecho, round(score, 3) AS similaridade

Ligação de entidades com tolerância a erro (índice FULLTEXT)

CALL db.index.fulltext.queryNodes('entity_fulltext', 'valv~1 OR "warcraft iii"') YIELD node, score
RETURN node.type AS tipo, node.name AS entidade, round(score, 3) AS score
LIMIT 6

Multi-hop: o jogo da Valve que veio de um mod de Warcraft III

MATCH p = (v:Entity {name: 'Valve'})<-[:DEVELOPED_BY]-(g:Game)-[:SEQUEL_OF]->(mod:Entity)-[:BASED_ON]->(w:Entity)
WHERE w.name STARTS WITH 'Warcraft III'
RETURN p

Menor caminho entre League of Legends e Dota 2 (shortestPath)

MATCH (a:Entity {name: 'League of Legends'}), (b:Entity {name: 'Dota 2'})
MATCH p = shortestPath((a)-[:BASED_ON|SEQUEL_OF|DEVELOPED_BY|CREATED_BY|PUBLISHED_BY|SUBSIDIARY_OF*..6]-(b))
RETURN p

PageRank (GDS): centralidade usada para ordenar a vizinhança

CALL gds.graph.project('kg', ['Entity'], {ALL: {type: '*', orientation: 'UNDIRECTED'}});
CALL gds.pageRank.write('kg', {writeProperty: 'pagerank', maxIterations: 40});
CALL gds.louvain.write('kg', {writeProperty: 'community'});
// nesta carga: 23 comunidades, modularidade 0,53 (o Louvain varia um pouco a cada execução; no artigo foram 24)

MATCH (e:Entity)
RETURN e.name AS entidade, e.type AS tipo, round(e.pagerank, 3) AS pagerank
ORDER BY pagerank DESC
LIMIT 10

Louvain (GDS): comunidades do grafo

MATCH (e:Entity)
WITH e.community AS comunidade, count(*) AS entidades, collect(e.name)[..5] AS exemplos
RETURN comunidade, entidades, exemplos
ORDER BY entidades DESC
LIMIT 8

7 - Redução de alucinação

  • Na ingestão: só entra no grafo a relação cuja frase de evidência aparece literalmente no artigo.
  • Na recuperação: sem entidade citada e com similaridade abaixo de 0,924, a pergunta é tratada como fora do domínio e o sistema recusa antes de gerar.
  • Na geração: toda afirmação cita uma tripla [T#] ou trecho [C#], e um verificador remove citações que não existem. Sem contexto suficiente, a resposta é “Não encontrei essa informação no grafo.”
  • Text-to-Cypher somente leitura: o filtro bloqueia CREATE, MERGE, DELETE e SET, e a consulta roda numa transação de leitura. Confiança = ligação (0,4) + estrutura (0,3) + fundamentação (0,3).

8 - Avaliação

  • 26 perguntas (12 de um salto, 9 de dois ou mais saltos e 5 fora do domínio), medindo o contexto recuperado contra um RAG vetorial puro no mesmo índice.
  • Suporte completo: 100% no GraphRAG contra 71,4% no vetorial. Recall em 2+ saltos: 1,00 contra 0,77. Recusa correta fora do domínio: 100% contra 0%.
  • Custo: contexto cerca de 3 vezes maior (7.159 × 2.352 caracteres) e latência mediana de 320 ms contra 14 ms, ainda pequena perto do tempo de geração de um LLM.
  • Limitação: as perguntas foram escritas pela equipe a partir do grafo e dois ajustes foram feitos nesse mesmo conjunto, então os 100% mostram que o mecanismo funciona, não a taxa em perguntas novas.

9 - Como rodar

cd backend
uv sync                                    # dependências
uv run python -m app.ingest.load --reset   # schema, carga, embeddings, PageRank e Louvain
uv run streamlit run streamlit_app.py      # interface
uv run python -m app.eval.run_eval         # avaliação GraphRAG × RAG vetorial
